## Proposito del bloque

Este bloque del Atlas reune los conceptos basicos necesarios para entender como se diseña, estructura y mantiene una aplicacion desde el punto de vista de arquitectura de software.

La idea es que sirva como referencia cuando:

- Se inicia un proyecto nuevo.
    
- Se quiere revisar buenas practicas de diseño.
    
- Se necesita refrescar conceptos antes de desarrollar o auditar un sistema.
    

---

## Orden sugerido de lectura

Lectura en orden logico, pensada como “de lo mas general a lo mas concreto”:

1. [[Patrones de Software]]  
    Introduce las formas tipicas de organizar una aplicacion (MVC, MVT, MVVM, Clean Architecture).
    
2. [[Ciclo de Vida del Software (SDLC)]]  
    Explica las fases por las que pasa un proyecto desde los requisitos hasta el mantenimiento.
    
3. [[Principios SOLID]]  
    Presenta principios de diseño para escribir codigo mas mantenible y escalable.
    
4. [[Buenas Practicas Codigo]]  
    Resume convenciones generales para organizar, nombrar y estructurar el codigo.
    
5. [[Arquitectura de Aplicaciones Web Modernas]]  
    Describe como se ven hoy en dia las aplicaciones web: frontend, backend, APIs, bases de datos y servicios externos.
    
6. [[Capas de una aplicacion]]  
    Explica la idea de dividir la aplicacion en capas (presentacion, logica, datos, dominio, infraestructura).
    
7. [[Arquitectura de controladores y servicios]]  
    Baja al detalle de como separar controladores, servicios y repositorios en la practica.
    
8. [[Diseño de APIs]]  
    Define como diseñar endpoints HTTP de forma clara, coherente y mantenible.
    
9. [[Redes esenciales para desarrollo web]]  
    Resume conceptos de redes aplicados a desarrollo: HTTP, HTTPS, CORS, puertos, DNS, proxies, etc.
    
10. [[Documentacion tecnica de proyectos]]  
    Explica que documentar en un proyecto (README, arquitectura, APIs, decisiones tecnicas, despliegue).
    
11. [[Arquitectura orientada a pruebas]]  
    Muestra como estructurar el codigo para que sea facil de probar (unitarias, integracion, E2E).

## Uso recomendado del indice

- Como punto de entrada al bloque de Arquitectura y Fundamentos.
    
- Como referencia rapida para decidir que nota leer cuando haya dudas concretas (por ejemplo, APIs, redes, documentacion).
    
- Como guia de estudio: seguir una de las rutas segun el objetivo del momento (desarrollo, refactorizacion, pentesting).
    

Este indice no sustituye los enlaces entre notas, pero proporciona una lectura lineal sugerida para evitar perderse cuando el grafo de nodos crezca demasiado.
